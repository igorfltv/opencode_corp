# Что добавить для корпоративного контура

## Ближайшая итерация

1. **Настоящий SSO и жизненный цикл устройства.** OIDC Authorization Code + PKCE,
   refresh token в OS keychain, список активных устройств, удалённый отзыв. Для SSH
   и удалённых серверов — device flow. `/whoami` показывает роли и время истечения доступа.
2. **Управляемые версии конфига.** Подписанные ревизии, preview diff через `/config_diff`,
   группы rollout, canary и last-known-good rollback. Неприменимый конфиг не ломает работу.
3. **Каталог моделей и квоты.** `/models_corp` показывает разрешённые модели, доступный
   контекст, очередь, ограничения по данным и остаток бюджета. `/usage` объясняет затраты
   без публикации исходного кода. Квоты и доступ проверяются на gateway.
4. **Поддержка без утечки данных.** `/doctor` проверяет TLS, proxy, SSO, версии, latency и
   конфиг; `/support_bundle` сначала показывает состав диагностического архива. Секреты,
   промпты, исходники и содержимое файлов по умолчанию исключены.

## После пилота

5. **Каталог доверенных skills и MCP.** Подпись издателя, версии, changelog, история
   одобрения, pin/rollback, совместимость с версиями OpenCode и явное описание доступов.
   Установка MCP не должна автоматически выдавать доступ к внешним сервисам.
6. **Профили по командам и типу данных.** Backend выдаёт engineering/data/support
   профиль и допустимые endpoints. Для закрытых репозиториев доступны только внутренние
   модели. Правила маршрутизации и data residency закрепляются на сервере.
7. **Работа при деградации.** Светофор с временем ожидания, запланированными работами
   и альтернативными разрешёнными моделями; пользователь явно выбирает переключение.
   Последний валидный конфиг работает offline в пределах политики организации.
8. **Аудит и observability.** События auth/config/skills, причины отказов, correlation ID,
   метрики задержек и ошибок. Состав телеметрии документирован; код и запросы к модели
   не включаются без отдельной политики и необходимости.
9. **Корпоративное обновление клиента.** Совместимые версии OpenCode/плагина, тестовая
   группа, rollout по отделам, откат bundle и проверка подписи дистрибутива.
10. **Командные шаблоны.** `/onboard`, `/review`, `/incident`, `/release_check` собираются
    из утверждённых skills. Изменения в репозитории и действия во внешних системах
    остаются явными задачами пользователя.

Приоритет для пилота: SSO → signed config и rollback → диагностика → каталог моделей
и квоты. Автоматическую установку новых привилегированных инструментов и передачу
исходного кода в телеметрию не стоит включать в начальные настройки.
